# Design Pillars

## 1. Original identity

This project is its own RPG. Other games and media are reference points, not canon.

## 2. Permanent, meaningful progression

Progress should continue to matter. Avoid content treadmills that invalidate yesterday's work. Prefer additive content, sidegrades, new uses, new knowledge, and new interactions over constant replacement.

## 3. Freedom without directionlessness

Players should be able to act, refuse, explore, sequence-break, and solve situations differently. The world reacts logically. Freedom should not mean dumping a giant map of disconnected destinations on the player.

## 4. Teach through situations

Do not introduce systems because a tutorial checklist says it is time. Introduce them because a character or problem makes the system relevant.

Examples:
- Marlow's sick troll makes Potion Making matter.
- Garrick's local contracts make Hunting matter.
- Sylvie's kitchen makes Cooking matter.

## 5. One mental model at a time

The opening may expose several future systems, but it should actively teach only the currently relevant one. Avoid tutorial avalanches, currency showers, and menu spam.

## 6. World first, interface second

Useful information should exist in the environment whenever practical. Clues are physical clues. Cooking is read through food and cookware. Rooms physically exist upstairs. The board is physically behind Garrick.

UI should support the world, not replace it.

## 7. Systems should interlock

Hunting, Potion Making, Cooking, Smithing, gathering, equipment, rooms, and future professions should feed one another. Avoid isolated skill bars that exist only to make numbers rise.

## 8. Old content should gain new relevance

Progression should sometimes let players extract new value from familiar creatures, ingredients, areas, or equipment. Example: higher Hunting knowledge can reveal new materials from old creatures.

## 9. Respect player time without removing all friction

Travel, gathering, preparation, and quiet moments can be valuable when they create place, anticipation, planning, or meaningful output. Remove meaningless friction, not all friction.

## 10. Avoid the misery zone

Do not create activities that require high attention while offering trivial decision-making and payoff. If something asks for attention, it should ask the player to notice, choose, execute, or learn something meaningful.

## 11. Failure should teach where possible

Missing an optional clue should reduce information, not brick a quest. Beginner Cooking mistakes should create understandable consequences rather than constant hard resets. Combat failure can still have normal stakes.

## 12. Characters are part of progression

Relationships should change how spaces and people behave toward the player.

Example progression:
- Sylvie first says: **"Out."**
- Later she may say: **"Need the stove?"**

That behavioral change is progression.

## 13. Humor needs contrast

Preserve charm, dry humor, odd discoveries, and memorable personalities, but do not make every line a joke. Grounded stakes and quiet moments give weirdness room to land.

## 14. Starting weak matters

Do not hand new characters impressive gear, sprawling skill lists, or endgame systems they cannot contextualize. The first room, first coin goal, first potion, first hunt, and first cooked meal should matter because the player started with less.

## 15. No obvious morality buttons when knowledge can drive choice

When a non-lethal Hunting resolution exists, it should arise because the player understood creature behavior or habitat, not because the game displayed GOOD OPTION / EVIL OPTION.
